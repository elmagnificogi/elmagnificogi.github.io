# 结构：比禁词更假的那一层

洗词洗不掉「这篇在上课」。本博客要像人写，先改骨架。

对照范文（人写的）：

- `_posts/2026-08-27-Car-Record.md`
- `_posts/2026-07-21-CBD-Publisher-OpenVSX.md`

不要把当前这篇 Agent 草稿当范文。草稿越完整，学它越假。

## 人怎么开头

先写我最近碰到什么、卡在哪。

- 「两次都在跟天气预报对赌，两次都输了。」
- 「本以为 Cursor 搜一下就能装。结果发现……免得下次又忘。」

不要：关键点写在前面、所以目标很明确、整理时按四段来写、你该怎么做。

## 禁止的骨架

用户没要求就不要用：

- 每节固定「案例 / 宏观 / 结论 / 应对」
- 「为什么 → 迁移 → 对比 → 上手」这种产品说明书目录（记踩坑可以按时间走）
- 把别人的话收成 1、2、3 再加习惯清单
- 每块都写满；短的就短，三句话加两张图可以结束
- Summary 复述全文、把各节译成标签表
- 结尾升华：神或魔鬼、锋利的刀、主动权、时代

## 句子不要焊成对仗

偶尔一次「不是 A 是 B」可以。不要连续用「一头……一头……」「真正的 X 是 Y」「逻辑是一样的」把整篇焊住。

人一句一个拍子：偷鸡不成蚀把米；谁这么闲；等了个寂寞。

## Summary

剩一句现在还想说的。不要复习，不要交作业。

- 可以：「控车确实比以前强了，看还有没有机会破圈速。」
- 不要：把刀、逃避、主动权再讲一遍。

## 起草时

用户丢的是经历、链接、报错、截图。按时间或按坑往下写。不要先立教学大纲再填空。空槽不要补「应对」。Foreword 和 Summary 能短则短；用户没写就不替他发明中心思想。
